# Публикация без WordPress

## Универсальные настройки хостинга

Для Netlify, Cloudflare Pages, Render Static Sites и других Node-based static hosts:

| Параметр | Значение |
|---|---|
| Node.js | 22.12+ или 24+ |
| Install command | `npm ci` |
| Build command | `npm run build` |
| Publish directory | `dist/client` |

Сервер PHP и база данных не нужны. Каждый маршрут уже имеет физический `index.html`, поэтому специальный SPA rewrite не требуется.

## Ручная загрузка

```bash
npm ci
npm run build
```

После успешной проверки нужно загрузить содержимое `dist/client` в корневую директорию сайта на хостинге.

Важно загружать именно содержимое папки, чтобы корневой `index.html`, `assets`, `media` и вложенные маршруты находились на одном уровне.

## Доступные варианты

- `npm run build` — основной независимый статический релиз.
- `npm run build:github-pages` — релиз в `/svetlana-ilina/`.
- `npm run build:sites` — пакет для Sites.
- `npm run build:wordpress` — необязательное обновление локальной WordPress-темы.

## Текущая публикация GitHub Pages

Репозиторий: `https://github.com/MystAxe/svetlana-ilina`, ветка `main`. Существующий `.github/workflows/pages.yml` собирает и публикует сайт после push. Подтверждённый адрес текущего размещения: `https://mystaxe.github.io/svetlana-ilina/`.

В `.env.github-pages` заданы `GITHUB_PAGES_BASE=/svetlana-ilina/` и `SITE_PUBLIC_ORIGIN=https://mystaxe.github.io`. Обычная локальная сборка сохраняет base `/`. Выбран красный Hero; чёрный вариант остаётся в исходниках. Отправка в remote `sites` для этой итерации не требуется.

## Что не зависит от хостинга

Навигация, истории, фильтры, тест и видео работают полностью на frontend. Текущая форма и отправка результатов теста не имеют сетевого backend: смена хостинга сама по себе не добавит прием заявок. Перед публичным запуском формы потребуется отдельно подключить API или сервис отправки.

## Метаданные ссылок

Перед сборкой опубликованной версии задайте `SITE_PUBLIC_ORIGIN` — согласованный HTTP(S)-адрес сайта без пути и завершающего маршрута. Для размещения в подпапке используется существующий `GITHUB_PAGES_BASE`. Значение не берётся из HTTP-заголовков посетителя.

`config/socialMetadata.ts` добавляет Open Graph и X title/description из соответствующего HTML. Общая обложка — `public/og.png`. У историй используются только их собственные изображения; история без согласованных медиа и статьи без обложек не наследуют общую картинку.

Если адрес не задан, title/description сохраняются, а абсолютные `og:url`, `og:image` и `twitter:image` не выдумываются. После задания адреса нужна новая сборка.
